\title{\Large \bf Closing the Effect Gap:\\
  A Layered Reference Monitor for LLM Agents}
\author{Anonymous submission}
\maketitle

\begin{abstract}
Agent defenses increasingly restrict which tool calls a language model may
issue. This is necessary but not sufficient. Once a call is approved, its
implementation may resolve a different file, open an undeclared socket, or
return sensitive data that later leaves through model context or an output
callback. We call the difference between an authorized call and its reachable
effects the \emph{effect gap}.

We present \sys, a layered reference monitor for LangGraph. A single router
mediates framework objects---including calls, state, checkpoints, model input,
and output---while a confined worker and the host kernel mediate files, syscalls,
and resources. Policy produces an exact, platform-neutral grant. The runtime
releases a worker only after exact-or-tighter lowering and activation evidence
bind that grant to the worker and enforcing mechanisms. Open object classes
extend the same contract to application resources without changing the policy
language.

Eight executable canaries demonstrate the effect gap: call-boundary defenses
approve policy-conformant calls whose implementations reach unauthorized sinks.
For the implemented boundary, a source-bound certificate verifies all 21
catalogued router obligations; an independent verifier passes 15,744 Tool API
conformance cases; and all 151 focused router, object-manager, and Linux tests
pass, exercising descriptor-bound Landlock rules, raw syscalls, descendants,
and activation failures. Policy-only
mediation adds 13.2\% latency in our recorded microbenchmark. We do not claim
whole-framework complete mediation: several upstream placement paths remain
open, and the paper reports them as coverage failures rather than redefining
them out of scope.
\end{abstract}

\section{Introduction}

Suppose a user asks an agent to read \code{reports/q3} and summarize it in a
finance channel. The model proposes exactly that call. A symbolic policy checks
the tool name and path, finds both authorized, and allows execution. The
decision is correct. The system may still be insecure.

The admitted implementation can join the approved relative path against an
attacker-controlled base, read \code{payroll.csv}, open a socket, and return the
secret. Even if the tool process cannot transmit directly, the framework may
write the result into graph state, place it in the next model prompt, or publish
it through a callback. None of these effects contradicts the decision that the
\emph{proposed call} was allowed. They occur below or after the point where the
decision was made.

This distinction matters because recent agent defenses have made the call
boundary substantially stronger. Progent expresses symbolic policies over tool
names and arguments and checks that unapproved policy updates only narrow
authority~\cite{progent}. SEAgent applies mandatory policy to an agent
information-flow graph~\cite{seagent}. CaMeL separates trusted control flow from
untrusted data and uses capabilities to protect data flows~\cite{camel}. These
systems address important parts of the problem. Our question is complementary:
\emph{what must the runtime guarantee after it decides to allow a call?}

Figure~\ref{fig:motivation} illustrates the gap. Call authorization constrains a
structured request. Security ultimately concerns the effects that execute: host
objects such as files and sockets, and framework objects such as state,
checkpoints, model context, and output destinations. A complete boundary must
mediate both kinds. The kernel does not understand a graph channel or Slack
destination; an agent framework cannot intercept raw \code{open(2)} inside
hostile code. Neither layer is sufficient alone.

  \centering
  \includegraphics[width=\textwidth]{figures/motivation.pdf}
  \caption{The effect gap. An exact call-boundary decision does not constrain
  effects inside the admitted implementation (left). \sys composes framework
  mediation with host confinement so the worker receives only the authority in
  the grant (right).}
  \label{fig:motivation}
\end{figure*}

We present \sys, a layered reference monitor integrated into LangGraph. The
design follows the operating-system pattern of composing kernel mediation with
user-space object managers for resources the kernel does not own. SELinux-aware
X, D-Bus, and PostgreSQL use this structure~\cite{selinuxnotebook,sepgsql};
\sys applies it to agent runtimes. LangGraph becomes the object manager for
framework-owned resources, and the host kernel remains the monitor for OS
resources.

Three principles organize the system. First, all framework operations enter one
refusing dispatch path, \code{HostRouter}. Second, policy names semantic
authority rather than Linux mechanisms: author-owned discretionary policy
constructs a finite candidate, and mandatory policy may only remove authority.
Third, a decision or plan is not proof of enforcement. A worker is released only
after activation evidence binds the exact grant, its lowering, the worker, and
the mechanisms that are active.

This paper makes three contributions:

\begin{itemize}
  \item We identify and experimentally demonstrate the \emph{effect gap} between
  authorizing a tool call and bounding the effects of its implementation and
  subsequent framework data paths.
  \item We design a layered reference monitor that composes one framework object
  manager with exact host confinement, restrict-only policy composition, open
  semantic object classes, and evidence-gated execution.
  \item We implement the design in LangGraph and evaluate its current boundary
  using executable canaries, a source-bound router certificate, exhaustive Tool
  API conformance, Linux integration tests, and policy-path benchmarks. We also
  publish the paths that remain outside the complete-mediation claim.
\end{itemize}

\section{The Effect Gap}
\label{sec:gap}

\subsection{Calls are requests, not effects}

Let a proposed call be $c=(p,t,a,h)$: principal $p$, tool $t$, arguments $a$,
and security history $h$. A call monitor computes an authorization decision
$D(c)$. Let $G(c)$ denote the authority intended by an allow decision, and let
$E(t,a)$ be the effects reachable from executing the implementation and
publishing its result. The desired property is

\begin{equation}
  E(t,a) \subseteq G(c).
  \label{eq:effect}
\end{equation}

Evaluating $D(c)$ establishes that $c$ is admitted; it does not establish
Equation~\ref{eq:effect}. Tool metadata cannot prove how a hostile
implementation resolves names, which dependencies run at import time, or which
ambient descriptors it inherits. Likewise, a host sandbox does not know whether
a result may enter a model prompt or cross a destination's clearance.

The gap appears in ordinary software patterns:

\begin{itemize}
  \item A policy approves a relative path before the implementation resolves it
  against an attacker-controlled directory.
  \item A URL rule approves HTTPS while the implementation accepts a different
  scheme or follows a redirect through an ambient client.
  \item A mail rule validates one recipient while the implementation expands a
  list or uses a broader credential.
  \item A read-confined call returns a secret to state; a later send-confined
  call transmits it. Each call is locally valid, but their composition is not.
\end{itemize}

The first three require enforcement below the implementation interface. The
fourth requires mediation of framework state and publication across calls.

\subsection{Reference-monitor requirements}

We adapt the classic reference-monitor requirements to an agent runtime. The
boundary must provide:

\paragraph{Complete mediation.}
Every operation on an in-scope object must cross a refusing path. Scope cannot
depend on whether the default policy happens to allow an operation.

\paragraph{Tamper resistance.}
Untrusted tools and nodes cannot modify the router, policy, grant, audit state,
or another tool's execution authority. They do not execute in the coordinator.

\paragraph{Verifiable enforcement.}
The system records not only the authorization decision, but also how every grant
line was enforced and whether those mechanisms were active for this worker.

\paragraph{Monotonic authority.}
Preparation, delegation, policy modules, and lowering may preserve or reduce
authority; they may not silently widen it. An unsupported rule denies unless an
operator explicitly accepts a degraded, non-confining execution.

\subsection{Threat model}

The adversary controls model outputs, retrieved data, tool arguments, untrusted
tool and node code, dependencies loaded after confinement, and subagent prompts.
It may exploit retries, argument rewriting, path races, import side effects,
malformed results, resource exhaustion, cancellation, and stale checkpoints.

The framework TCB contains authentication, the coordinator and router, policy
backend, modules, canonicalizers, grant compiler, framework adapters, audit and
flow stores, and operator-promoted trusted nodes. The host TCB contains the
kernel, launcher, enforcement adapter, and supervisor. Kernel compromise, side
channels, denial of service, the model-provider channel, and trusted-node reads
are outside the claim. Task intent is also separate: exact authority does not
prove that an allowed action is beneficial.

\section{Design Overview}
\label{sec:overview}

Figure~\ref{fig:architecture} shows the two-layer design. A framework operation
enters \code{HostRouter} with an authenticated principal and immutable request.
Policy constructs an exact grant. Framework effects remain inside the object
manager; host effects are lowered by a trusted parent into a fresh worker's
Landlock, seccomp, and resource-control configuration. Execution begins only
after an activation receipt passes verification.

\subsection{One scope rule}

An operation is in scope if and only if a hook on the single dispatch path can
refuse it. This rule avoids two tempting but unsound shortcuts. First, a
permissive default does not remove an object from the security model. Second,
adding an adapter or a passing example does not establish that every upstream
path uses it. Missing placement remains a coverage failure.

\sys defines ten object classes, summarized in Table~\ref{tab:objects}. The
kernel owns HostResource. LangGraph owns the other nine. \code{ToolNode} and
\code{guarded\_tool} are callers into \code{HostRouter}, not separate security
boundaries.

\subsection{Authorization, enforcement, evidence}

The design separates three questions that are often collapsed:

\begin{enumerate}
  \item \emph{Authorization:} what exact authority should this operation have?
  \item \emph{Enforcement:} which components make all other authority
  unavailable?
  \item \emph{Evidence:} what establishes that those components protected this
  execution?
\end{enumerate}

A policy decision answers only the first. An adapter capability name answers
neither the second nor the third. \sys carries an immutable grant through all
three stages and binds their outputs by digest and execution identity.

\section{Framework Object Manager}
\label{sec:objects}

\subsection{Single-path dispatch}

\code{HostRouter} is the only interface that may enter protected execution
authority. Sync and async APIs share the same contracts. Every physical retry
receives a fresh request and decision; this matters because LangGraph wrappers
may call their \code{execute} continuation repeatedly with changed arguments.
Mediation outside that continuation would authorize one request and execute
another.

Child dispatch always runs credential-transfer policy and an explicit subset
check, including same-principal branches. The audit therefore records identity
transfers instead of treating them as invisible no-ops. A worker may request a
nested tool only over an authenticated channel bound by the host; caller-supplied
tool names and principal fields do not establish origin.

\subsection{State, checkpoints, model input, and output}

Per-call confinement alone cannot prevent cross-call exfiltration. The object
manager therefore mediates the paths that carry data between calls:

\paragraph{State and store.}
Keys have owners and labels. Tools receive only declared state channels and a
mediated store interface. State writes and reads are separate operations so
mandatory policy can constrain both provenance and use.

\paragraph{Checkpoints.}
Restore verifies a keyed hash chain, predecessor, monotone sequence, and
principal binding. A valid serialized shape is not sufficient: replay and
cross-principal substitution are rejected.

\paragraph{Model invocation.}
Policy runs before prompt assembly and may deny or strip labeled values. This is
the last framework boundary before data reaches the model-provider channel.

\paragraph{Output.}
Policy sees content labels, destination clearance, and the proposed effect. Its
verdict is allow, deny, redact, or escalate. Tool post-processing and output
mediation are distinct; a safe return value may still target an unsafe
destination.

\subsection{Cross-call flow scheduling}

Operators may configure a coarse session label in addition to per-operation
authorization. Each possible read has a conservative source label; each outward
effect may have a sink ceiling. Before parallel fan-out, source labels join into
durable session state. A sink proceeds only when the accumulated label is below
its ceiling. Reservations span execution, post hooks, audit, and confirmed
worker termination, preventing a sink from racing a concurrent source.

This is intentionally not automatic taint tracking. Its guarantee depends on
complete labels and mediation of every outward channel. Unknown effective
authority cannot be assigned a convenient public label.

\subsection{Certifying router placement}

The router certificate is a bounded, path-sensitive authorization-state
analysis over Python ASTs. It tracks a successful decision's permission class,
principal identity, request identity, and single-use dispatch obligation.
Changed objects, repeated dispatch, unknown calls, unsupported statements, and
path-budget exhaustion remain unresolved. Reviewed helper contracts are
source-hash bound so implementation drift invalidates dependent obligations.

This analysis does not prove Python semantics or policy correctness. It provides
reviewable evidence for a finite router boundary. The protected-operation
inventory is maintained separately, ensuring that a missing path cannot
disappear merely because the checker did not certify it.

\section{From Policy to Enforced Grant}
\label{sec:grant}

\subsection{Constructive DAC, restrictive MAC}

A tool profile proposes finite authority. The tool owner and invoking principal
must both permit each candidate line; explicit shares may contribute delegated
authority. Undeclared tools receive no resource or caller authority. A required
\code{need} line that does not survive denies the operation; an optional
\code{want} line is removed.

Mandatory modules run after discretionary construction and may emit only
forbids, labels, or a restrictive verdict. They cannot introduce a permit or
mutate the candidate. The default Cedar backend creates one ephemeral permit per
surviving discretionary line, then evaluates operator-owned forbids. Any schema,
validation, evaluation, or diagnostic failure denies~\cite{cedar}.

Preparation is a separate trusted operation. Its output is normalized and
reauthorized; a resource-changing transform must prove semantic attenuation over
typed actions and selectors. String length, structural similarity, and module
trust are not authority orderings.

\subsection{Open semantic object classes}

Agent applications manipulate resources a framework cannot enumerate in
advance: database tables, secrets, queues, browser origins, cloud objects, and
service recipients. A \code{class} declaration names an operation vocabulary,
object kind, trusted canonicalizer, policy-visible attributes, enforcement
locus, and lowering adapter. Tool profiles then request concrete \code{need} or
\code{want} lines over that class.

The registry derives typed Cedar actions and entities from the declaration.
Canonicalizers may emit only declared attributes. Every class must name a
kernel, broker, resource-side, or framework enforcer. This keeps the grammar
open without making enforcement optional.

\subsection{Exact grants and conservative lowering}

The immutable grant binds the principal, request, tool artifact, policy version,
rules, and operator-owned runtime baseline. A rule contains an action, semantic
selector, conditions, requirement identity, and provenance. The baseline makes
interpreter roots, tool packages, descriptors, environment, and protocol
channels visible authority rather than adapter entitlements.

Every grant line lowers as \emph{exact}, \emph{tightened}, or
\emph{unsupported}. Exact preserves the represented authority; tightened
implements a subset; unsupported denies. An operator may explicitly waive a
class, but the waiver is bound into the grant and yields a degraded receipt with
no confinement claim. The adapter may never approximate an endpoint rule with
``network allowed'' or add a runtime dependency after policy.

\subsection{Activation receipts}

The coordinator creates a nonce and execution context. Before release, each
enforcer returns evidence covering its exact obligations. The receipt binds the
principal, request, artifact, grant, lowering result, worker identity,
mechanisms, host capabilities, and expiry. Missing, duplicate, additional,
stale, or digest-mismatched evidence fails verification.

A plan hash proves agreement about bytes. It does not prove that a filter was
installed on the process about to execute. The release barrier is the point
where intended authority becomes an enforced execution.

\section{Linux Enforcement}
\label{sec:linux}

The Linux backend uses Landlock as its primary filesystem mechanism, seccomp for
syscall classes, cgroup v2 or rlimits for resources, and a supervisor for
lifetime. It requires no user namespace. This choice avoids making confinement
depend on unprivileged namespace settings that distributions increasingly
restrict~\cite{landlock,seccomp}.

\subsection{Confinement before import}

A single-threaded trusted template starts without untrusted imports. For each
call, the parent resolves grant paths with \code{openat2} using
\code{RESOLVE\_BENEATH} and \code{RESOLVE\_NO\_MAGICLINKS}, constructs the
complete Landlock ruleset, optionally creates a fresh cgroup, and forks a worker.
The worker closes every non-protocol descriptor, sets \code{NoNewPrivs}, calls
\code{restrict\_self} on the one ruleset descriptor, installs seccomp and
limits, and only then imports the target. It never receives path descriptors or
root router authority.

The runtime baseline includes the interpreter, standard library, tool packages,
\code{/dev/urandom}, temporary storage, and protocol channels. These appear in
the grant and evidence. A missing baseline denies; the adapter cannot repair it
with ambient mounts or inherited descriptors.

\subsection{Kernel semantics}

Filesystem rules bind resolved kernel objects and access masks. The parent, not
the worker, constructs all rules. Create authority binds the resolved parent.
Tests exercise a granted file, a second file, direct raw \code{open(2)}, a
grandchild process, and \code{openat2} magic-link resolution.

Landlock network rules name ports, not endpoints. The phase-one seccomp profile
tightens network authority to no new \code{socket} or \code{connect}; endpoint
and name policy require a broker. Target-specific \code{EXECUTE} can be lowered
with Landlock, but phase one similarly tightens execution to none. Seccomp
returns \code{EPERM} for ordinary socket operations and kills the worker for
\code{ptrace}, process-VM reads, BPF, and namespace creation.

Delegated cgroup v2 controllers provide CPU, memory, PID limits, and
\code{cgroup.kill} descendant teardown. Without delegation, the receipt records
the representable rlimit and pidfd fallback. It never relabels an unavailable
physical-memory guarantee as exact. A supervisor owns wall time. If cancellation
cannot establish whether an irreversible effect committed or the worker died,
the outcome is \code{INDETERMINATE} and flow reservations remain durable.

\section{Security Argument}
\label{sec:argument}

We state the claim for an operation whose framework route is certified and whose
host receipt verifies. It is conditional on the TCB and mechanism semantics in
Section~\ref{sec:gap}.

\paragraph{No policy grant path.}
Owner and principal/share policy construct candidate lines. Mandatory policy is
forbid-only. Preparation and delegation require semantic subset checks. Thus no
module ordering, transform, or child dispatch can convert prior denial into
authority.

\paragraph{No silent lowering expansion.}
Every semantic rule and baseline line has exactly one enforcement disposition.
Exact and tightened lowerings represent subsets of the grant. Unsupported lines
deny or produce an explicitly degraded, non-confining receipt. Therefore a
verified enforced receipt cannot silently retain broader authority in an owned
domain.

\paragraph{Worker authority is bound before execution.}
Untrusted imports occur only after descriptor cleanup, Landlock restriction,
seccomp, and resource controls. Receipt verification precedes the release
barrier and binds the observed worker to the request and grant. Worker output is
not accepted as setup evidence.

\paragraph{Framework effects remain mediated.}
For a certified router path, dispatch consumes authorization for the same
principal and immutable request. State, model, and output effects require their
own operations; authorization for tool invocation does not authorize them.

Together these properties establish Equation~\ref{eq:effect} for the certified
framework routes and supported host authority domains. They do not establish it
for an unplaced upstream path. That distinction is central: component evidence
is not promoted into a whole-system theorem.

\section{Evaluation}
\label{sec:evaluation}

We ask three questions:

\begin{itemize}
  \item \textbf{RQ1:} Does the effect gap arise in executable agent tools?
  \item \textbf{RQ2:} What portion of the layered boundary has concrete
  implementation evidence, and what remains open?
  \item \textbf{RQ3:} What is the cost of framework policy mediation?
\end{itemize}

The implementation is based on LangGraph 1.2.12. The layered architecture is
revision \code{53c5d317}; each recorded experiment retains its own revision,
hardware, and dependency identities. We separate dynamic canaries, bounded
source certificates, API conformance, kernel integration, and projections. No
projection is reported as runtime blocking evidence.

\subsection{RQ1: Executable effect-gap canaries}

We built eight deliberately vulnerable tools: file read, file write, shell,
SQL, fetch, email, Slack, and delegation. Each receives a policy-conformant call
but resolves or expands authority below the checked interface. Calls were
generated once by local Qwen3-8B at temperature zero and replayed identically.
Experiments use temporary directories, synthetic records, and loopback services;
no third-party deployment is attacked.

All eight unauthorized sinks were reached with no defense and after Progent
approved the policy-conformant calls. The same eight were reached behind each of
three tested generic LangChain wrappers (Eydii, Forge, and Nuggets). This result
does not show that their call policies are incorrect. It demonstrates precisely
the distinction in Equation~\ref{eq:effect}: approving the request does not
confine its implementation.

CaMeL addresses a stronger data-flow model. Under a generous assumption that all
relevant values remain untrusted-tagged, our static model marks all eight paths
covered. We separately reproduced one narrower post-validation case in which a
value trusted at the policy boundary became an absolute path during resolution.
That 1/1 result is not a general bypass claim against CaMeL.

\subsection{RQ2: Evidence and open coverage}

Table~\ref{tab:evidence} reports evidence at each layer. The router analyzer
discovers entries independently of the admission catalog and verifies all 21
current obligations under its documented contracts. The Tool API verifier
passes 15,744 cases across inherited execution surfaces and adapters. A focused
current run of router, object-manager, layered-verification, Landlock, and Linux
execution tests passes all 151 cases (4 warnings) in 15.84 seconds.

Implementation review organized composition risk into six categories: binding
adapter effects to the effective authorized object; rerunning object DAC on
approval resume; covering every framework-supported value shape; partitioning
authoritative state and preserving labels; mediating every publication and
checkpoint API; and establishing process isolation plus authenticated object RPC
for untrusted nodes. The focused run includes regression tests for effective
store objects, resume reauthorization, and principal/session state partitioning.
Automatic coverage of every value, publication, checkpoint, and dispatch path,
plus an authenticated untrusted-node host, remains open. These are not cosmetic
TODOs: each is a route by which component-correct enforcement could fail to
compose.

An earlier frozen Linux milestone passed the complete 518-test prebuilt command
and 55 focused tests. We retain those results as historical compatibility
evidence, not as measurements of the current Landlock backend. Released-artifact
validation also passes CaMeL's 126 tests and three Progent checker-parity cases;
those validate our harness, not comparative security.

\subsection{RQ3: Policy-path overhead}

Matched \code{pytest-benchmark} cases invoke one no-op tool through a complete
synchronous \code{ToolNode}. The disabled-security median is 593.701~$\mu$s.
Capability-only mediation is 672.212~$\mu$s, a 13.2\% increase; five no-op
modules are 884.800~$\mu$s, a 49.0\% increase. Figure~\ref{fig:perf} shows the
relative cost.

\section{Limitations}
\label{sec:limitations}

\paragraph{Placement is incomplete.}
Adapters exist for the framework objects in Table~\ref{tab:objects}, but several
general graph, state, checkpoint, completion-callback, and publication paths
are not automatically routed. Direct Store references and trusted in-process
compatibility paths remain outside the composed claim.

\paragraph{Useful service confinement is phase two.}
Mail, SQL, cloud, and endpoint-scoped network tools require trusted brokers or
resource-side credentials. Today unsupported grants deny. That is safe by
refusal, not useful least-privilege execution.

\paragraph{Labels are configuration, not inference.}
Session scheduling is sound only if labels bound every actual read and every
outward channel is mediated. The system does not automatically infer task
intent, provenance, or declassification.

\paragraph{Evidence is local and software-rooted.}
Receipts do not protect against a compromised kernel, launcher, policy backend,
canonicalizer, label provider, or trusted module. The router analyzer is trusted
and has regression tests, not a machine-checked soundness proof. Landlock
constrains access to live objects; it does not provide snapshot integrity.

\paragraph{Evaluation is not yet complete.}
The canary suite is small and synthetic. Dynamic \sys rows for AgentDojo,
InjecAgent, and ASB, service-broker experiments, and fresh-worker latency remain
necessary before making broad utility or deployment claims.

\section{Related Work}

\paragraph{Agent privilege and information flow.}
Progent introduces expressive tool-call policies, automated policy construction,
and SMT-checked monotonic updates~\cite{progent}. SEAgent combines ABAC with an
agent information-flow graph~\cite{seagent}. CaMeL protects flows by separating
trusted control from untrusted data~\cite{camel}. \sys addresses the boundary
below and around an admitted call: hostile implementation effects, framework
objects, host confinement, and evidence that enforcement activated. Its coarse
session scheduler is less precise than CaMeL and explicitly conditional on
complete labels and sink mediation.

\paragraph{Agent-security evaluation.}
AgentDojo provides stateful tasks and indirect-prompt-injection security
cases~\cite{agentdojo}. InjecAgent contains 1,054 cases over user and attacker
tools~\cite{injecagent}; ASB spans multiple attack classes, scenarios, and
hundreds of tools~\cite{asb}. These benchmarks primarily measure behavioral
attack success and utility. Our canaries isolate whether an admitted
implementation retains unauthorized authority; the questions are complementary.

\paragraph{Reference monitors and hook placement.}
LSM separates fixed mediation hooks from policy, preserves discretionary checks,
and supports restrictive module composition~\cite{wright2002lsm,linuxlsm}.
SELinux user-space object managers extend the same architecture beyond kernel
objects~\cite{selinuxnotebook,sepgsql}. Prior work shows that authorization-hook
placement itself requires systematic analysis~\cite{zhang2002cqual}. \sys
adapts these ideas to framework objects and agent execution paths.

\paragraph{Sandboxing and authorization.}
Landlock provides unprivileged, monotonic restriction over filesystem and port
objects~\cite{landlock}; seccomp restricts syscall classes~\cite{seccomp}. Cedar
provides typed principal--action--resource--context policies with forbid-overrides
composition~\cite{cedar}. \sys uses Cedar for authorization and Linux mechanisms
for enforcement; neither is asked to model the other's domain.

\section{Conclusion}

Authorizing a tool call and bounding its effects are different security
problems. A precise policy can approve the right request while hostile code or
an unmediated framework path exercises the wrong authority. \sys closes this
effect gap by composing a framework object manager with host confinement and by
requiring evidence before execution.

The current implementation establishes this chain for a certified router subset
and a Linux host subset. It does not yet establish whole-framework complete
mediation, and the remaining placement failures are part of the result. That
honesty is not merely caution: a reference monitor is defined as much by the
paths it cannot miss as by the policies it can express.

\section{Ethical Considerations}

The bypass canaries target deliberately vulnerable tools in temporary
directories, synthetic databases, and loopback services. They do not probe or
modify third-party deployments. Canary values are fake and audit logs hash
arguments by default.

A security framework can create false confidence when its placement or host
support is incomplete. \sys mitigates that risk by denying unsupported grants,
stamping waivers as degraded, publishing the protected-operation inventory, and
separating component evidence from system claims. Operators remain responsible
for policy correctness, TCB maintenance, user notice, and recovery from
\code{INDETERMINATE} operations.
