\title{\Large \bf Closing the Effect Gap:\\
  A Layered Reference Monitor for LLM Agents}
\author{Anonymous submission}
\maketitle

\begin{abstract}
An agent can invoke an authorized tool and still perform an unauthorized
operation. Call policies constrain requests; host sandboxes constrain files and
processes. Neither alone preserves domain permissions, such as reading one
record in a database, across tool execution and subsequent data flows.
We present \sys, an extensible enforcement substrate for LangGraph. Independent
analyses supply resource requirements and evidence. The runtime combines
manifest requirements, principal authorization, and operator-owned mandatory
restrictions into an invocation grant, then enforces it through restricted
in-process APIs, resource mediators, or host-confined workers. Operator policy
is sealed before execution; graph-local configuration cannot remove it.
A provenance runtime supplies data and control dependencies to fixed policies
without granting analyzers permission to change those policies.
The implementation includes pump and SQLite mediators, host-dependent lowering,
and instrumented flow checks. Existing synthetic canaries demonstrate the gap
between call authorization and implementation effects. Historical component
results include 21 certified router obligations, 15,744 Tool API conformance
cases, and 13.2\% policy-path overhead. These results retain their original
snapshots; they do not measure the new analysis or broker paths. We state the
remaining coverage and trust assumptions explicitly rather than claiming
complete mediation of arbitrary Python programs.
\end{abstract}

\section{Introduction}

An agent is allowed to summarize Alice's record in a shared SQLite database.
Its tool call names the correct record and passes authorization. The admitted
implementation instead reads Bob's record. A call monitor sees no second
request, while a file sandbox permitting the database cannot distinguish its
records. Even a correctly confined read can leak later if its result reaches
an unauthorized model or output destination. The problem is preserving the
meaning of authorization across these boundaries.

Existing systems protect different parts of this execution. Progent checks
symbolic tool-call policies; CaMeL and SEAgent constrain agent information
flows~\cite{progent,camel,seagent}. NVIDIA APF combines Cedar grants and controls
with enforcement adapters. Nono and Sandlock derive process restrictions from
configured capabilities~\cite{apf,nono,sandlock}. These mechanisms establish
substantial overlap: policy composition, sandboxing, and host lowering are not
new. The missing connection in the reviewed paths is a common contract from
independently supplied tool requirements to the resource authority enforced for
each invocation.

Three boundaries make that connection difficult. First, an allowed call enters
a tool implementation whose internal effects may bypass the call monitor.
Second, domain authority can be finer than host authority: reading a file is
not permission to read every database record or calibrate a device reached
through that file. Third, local sandbox overrides or alternative execution
routes can weaken a restriction that was intended to be mandatory.
Table~\ref{tab:boundaries} compares these boundaries without treating a trusted
extension or documented configuration option as an exploit.

We present \sys, an extensible enforcement substrate integrated into LangGraph.
A manifest requests resource operations; it does not grant them. Principal
policy authorizes those requests, and operator-owned mandatory policy can only
remove authority. The resulting grant follows the invocation into a restricted
in-process API, a domain mediator, or a confined worker. The SQLite mediator,
for example, retains the database outside the worker and checks each record
operation against that grant. Framework mediation constrains subsequent model
submission and output.

\sys separates analysis from enforcement, following the LSM pattern of shared
mediation points and replaceable security modules~\cite{wright2002lsm,linuxlsm}.
A static analyzer, trace-based system, or human can supply requirements through
the manifest interface. Runtime analyzers supply findings and provenance to
preinstalled policies, not new permissions. Thus a new detector or policy need
not implement its own sandbox, resource broker, and framework hooks. The
extension contract is the contribution; automatic translation of arbitrary
existing inference systems is not claimed.

This paper makes three contributions:
\begin{itemize}
  \item An enforcement contract connecting manifest requirements, principal
  authorization, and mandatory restrictions to invocation-specific effects.
  \item A LangGraph implementation with sealed runtime MAC, restricted
  in-process admission, extensible resource mediators, host confinement, and
  provenance-aware policy hooks.
  \item An evaluation separating executable effect-gap canaries, bounded
  verification, host tests, and policy overhead from incomplete coverage and
  unevaluated extensions.
\end{itemize}

The current implementation supports specific mediated routes, not arbitrary
Python confinement. Trusted bootstrap, resource backends, and analyzers remain
in the TCB; unsupported routes under runtime MAC are refused. Component
certificates and demonstrations do not establish whole-framework completeness.


\section{The Effect Gap}
\label{sec:gap}

\subsection{Calls are requests, not effects}

Let a proposed call be $c=(p,t,a,h)$: principal $p$, tool $t$, arguments $a$,
and security history $h$. A call monitor computes an authorization decision
$D(c)$. Let $G(c)$ denote the authority intended by an allow decision, and let
$E_{B,H}(c)$ denote the authority-bearing effects reachable through runtime
boundary $B$ on host $H$, projected onto the claimed authority domains and
including publication of the result. For an enforced execution, the desired
property is

\begin{equation}
  E_{B,H}(c) \subseteq G(c).
  \label{eq:effect}
\end{equation}

Evaluating $D(c)$ establishes that $c$ is admitted; it does not establish
Equation~\ref{eq:effect}. Tool metadata cannot prove how a hostile
implementation resolves names, which dependencies run at import time, or which
ambient descriptors it inherits. Likewise, a host sandbox does not know whether
a result may enter a model prompt or cross a destination's clearance.

The gap appears in ordinary software patterns:

\begin{itemize}
  \item A policy approves a relative path before the implementation resolves it
  against an attacker-controlled directory.
  \item A URL rule approves HTTPS while the implementation accepts a different
  scheme or follows a redirect through an ambient client.
  \item A mail rule validates one recipient while the implementation expands a
  list or uses a broader credential.
  \item A read-confined call returns a secret to state; a later send-confined
  call transmits it. Each call is locally valid, but their composition is not.
\end{itemize}

The first three require enforcement below the implementation interface. The
fourth requires mediation of framework state and publication across calls.

A mandatory restriction must survive local configuration and execution changes.
Nono explicitly permits an intercept sandbox to replace, rather than narrow,
the base policy~\cite{nono}. This is an operator-authorized feature, but it
illustrates why a base sandbox is not necessarily a mandatory ceiling. APF
already has grants constrained by control forbids~\cite{apf}; our distinction
is their connection to each invocation's resource authority, not the existence
of mandatory rules. Similarly, call and flow monitors can be sound under
trusted-tool assumptions while needing additional enforcement for hostile tools.

The decisive experiment holds a rule fixed, such as ``Alice cannot read Bob's
record,'' and changes only the execution route: tool body, child process,
local override, or broker. A successful design must reject the effect or refuse
the unsupported route. A correctly configured external broker/sandbox is a
necessary baseline. These cross-system experiments remain distinct from the
existing synthetic canaries in Section~\ref{sec:evaluation}.

\subsection{Reference-monitor requirements}

We adapt the classic reference-monitor requirements to an agent runtime. The
boundary must provide:

\paragraph{Complete mediation.}
Every operation on an in-scope object must cross a refusing path. Scope cannot
depend on whether the default policy happens to allow an operation.

\paragraph{Tamper resistance.}
Untrusted tools and nodes cannot modify the router, policy, grant, audit state,
or another tool's execution authority. They do not execute in the coordinator.

\paragraph{Verifiable enforcement.}
The system records not only the authorization decision, but also how every grant
line was enforced and whether those mechanisms were active for this worker.

\paragraph{Monotonic authority.}
Preparation, delegation, policy modules, and lowering may preserve or reduce
authority; they may not silently widen it. An unsupported required obligation
denies. Explicit waivers are limited to obligations eligible for degradation;
they do not waive identity binding, default deny, or isolation before import.
Degraded executions do not carry the complete grant-subset claim. The
sealed runtime-MAC path rejects enforcement waivers entirely.

\subsection{Threat model}

The adversary controls model outputs, retrieved data, tool arguments, untrusted
tool and node code, dependencies loaded after confinement, and subagent prompts.
It may exploit retries, argument rewriting, path races, import side effects,
malformed results, resource exhaustion, cancellation, and stale checkpoints.

The framework TCB contains authentication, the coordinator and router, policy
backend, modules, canonicalizers, grant compiler, framework adapters, audit and
flow stores, and operator-promoted trusted nodes. The host TCB contains the
kernel, launcher, enforcement adapter, and supervisor. In deployment mode, the
deployment manager, its protected store, and approved runtime publishers also
belong to the TCB. Kernel compromise, side
channels, denial of service, and a provider's handling of data after authorized
submission are outside the claim. Trusted initialization and mediator code are
not confined by a tool-body certificate. Task intent is also separate: exact authority does not
prove that an allowed action is beneficial.

\section{Design Overview}
\label{sec:overview}

Figure~\ref{fig:architecture} shows the enforcement pipeline. Router-mediated
operations enter \code{HostRouter} with an authenticated principal and immutable
request; high-level resource tools use the object authorizer and dispatcher.
Policy constructs a grant. Framework effects use the object manager; a selected
Linux adapter constrains host effects. The Landlock path uses a fresh worker
with filesystem, syscall, and resource controls. The deployment-backed path uses
bubblewrap and seccomp. Their integration coverage differs, as detailed in
Section~\ref{sec:linux}. Host-confined execution requires verified activation before release.
The high-level object broker supplies a separate Landlock-based worker path;
restricted in-process tools use checked API terminals instead of a worker.
These contracts share authorization, but their enforcement evidence differs.

\subsection{Authorization, enforcement, evidence}

The design separates three questions that are often collapsed:

\begin{enumerate}
  \item \emph{Authorization:} what exact authority should this operation have?
  \item \emph{Enforcement:} which components make all other authority
  unavailable?
  \item \emph{Evidence:} what establishes that those components protected this
  execution?
\end{enumerate}

A policy decision answers only the first. An adapter capability name answers
neither the second nor the third. \sys carries an immutable grant through all
three stages and binds their outputs by digest and execution identity.

\section{Framework Object Manager}
\label{sec:objects}

\subsection{Single-path dispatch}

\code{HostRouter} is the only interface that may enter protected execution
authority. Sync and async APIs share the same contracts. Every physical retry
receives a fresh request and decision; this matters because LangGraph wrappers
may call their \code{execute} continuation repeatedly with changed arguments.
Mediation outside that continuation would authorize one request and execute
another.

Child dispatch always runs credential-transfer policy and an explicit subset
check, including same-principal branches. The audit therefore records identity
transfers instead of treating them as invisible no-ops. A worker may request a
nested tool only over an authenticated channel bound by the host; caller-supplied
tool names and principal fields do not establish origin.

\subsection{State, checkpoints, model input, and output}

Per-call confinement alone cannot prevent cross-call exfiltration. The object
manager therefore mediates the paths that carry data between calls:

\paragraph{State and store.}
Keys have owners and labels. Tools receive only declared state channels and a
mediated store interface. State writes and reads are separate operations so
mandatory policy can constrain both provenance and use.

\paragraph{Checkpoints.}
Restore verifies a keyed hash chain, predecessor, monotone sequence, and
principal binding. A valid serialized shape is not sufficient: replay and
cross-principal substitution are rejected.

\paragraph{Model invocation.}
Policy runs before prompt assembly and may deny or strip labeled values. This is
the last framework boundary before data reaches the model-provider channel.

\paragraph{Output.}
Policy sees content labels, destination clearance, and the proposed effect. Its
verdict is allow, deny, redact, or escalate. Tool post-processing and output
mediation are distinct; a safe return value may still target an unsafe
destination.

\subsection{Cross-call flow scheduling}

Operators may configure a coarse session label in addition to per-operation
authorization. Each possible read has a conservative source label; each outward
effect may have a sink ceiling. Before parallel fan-out, source labels join into
durable session state. A sink proceeds only when the accumulated label is below
its ceiling. Reservations span execution, post hooks, audit, and confirmed
worker termination, preventing a sink from racing a concurrent source.

Session reservations are distinct from the provenance runtime below. Their
soundness requires conservative read bounds, including runtime-baseline and
degraded authority, and mediation of outward channels. Unknown effective
authority cannot be assigned a public label.

\subsection{Replaceable analysis under fixed policy}
\label{sec:analysis}

The analysis runtime owns a registry, scheduler, canonical storage, provenance,
and scoped query interface. Plugins return findings and restrictive annotations;
their result schema rejects policy, rule, and grant fields. Security modules
interpret this evidence under configuration loaded before execution. Policies
and their digest remain fixed across findings, retries, and checkpoint resumes.
Approval remains input to one operation's existing permission chain and cannot
override another module's denial.

Required analyzers finish in dependency order before the protected operation.
Exceptions and deadlines produce unavailable evidence, not a clean finding;
configured required-analysis gates deny the operation. Late results cannot commit.
Every physical attempt binds a fresh snapshot to principal, session, normalized
and actual arguments, invocation, attempt, and host execution identity. Historical
query results cannot authorize a new execution. Developers and policy modules
access scoped immutable views of the same canonical records.

Provenance assigns identities to immutable value versions and records data and
control dependencies. Confidentiality and risk labels accumulate; allowed-reader
sets intersect. Opaque transformations retain all declared influences, and model
responses conservatively inherit submitted context. Plugins may add restrictions
and ancestry, not remove them. Trusted interpreter adapters can supply precise
selection and control dependencies within their declared semantics.
\code{AnalysisFlowPolicy} checks tools, model destinations, and output against
these labels and trusted read bounds. No declassification API is enabled.

Findings and provenance commit transactionally in SQLite. Authenticated
checkpoints bind policy, domain, and role configuration. Analyzers and adapters
remain trusted code: the runtime does not prove detector accuracy or discover
unreported native effects. Required coverage must be declared; unsupported
callbacks, reducers, caches, and custom nodes require adapters or refusal.

\subsection{Certifying router placement}

The router certificate is a bounded, path-sensitive authorization-state
analysis over Python ASTs. It tracks a successful decision's permission class,
principal identity, request identity, and single-use dispatch obligation.
Changed objects, repeated dispatch, unknown calls, unsupported statements, and
path-budget exhaustion remain unresolved. Reviewed helper contracts are
source-hash bound so implementation drift invalidates dependent obligations.

This analysis does not prove Python semantics or policy correctness. It provides
reviewable evidence for a finite router boundary. The protected-operation
inventory is maintained separately, ensuring that a missing path cannot
disappear merely because the checker did not certify it.

\section{From Policy to Enforced Grant}
\label{sec:grant}

\subsection{Constructive DAC, restrictive MAC}

A tool profile proposes finite authority. The tool owner and invoking principal
must both permit each candidate line; explicit shares may contribute delegated
authority. Undeclared tools receive no resource or caller authority. A required
\code{need} line that does not survive denies the operation; an optional
\code{want} line is removed.

Mandatory modules run after discretionary construction and may emit only
forbids, labels, or a restrictive verdict. They cannot introduce a permit or
mutate the candidate. The object authorizer checks the generated owner ceiling and principal/share
permits, then tests each candidate against operator and local forbids. Any schema,
validation, evaluation, or diagnostic failure denies~\cite{cedar}.

Preparation is a separate trusted operation. Its output is normalized and
reauthorized; a resource-changing transform must prove semantic attenuation over
typed actions and selectors. String length, structural similarity, and module
trust are not authority orderings.

\subsection{A mandatory ceiling across local configurations}
\label{sec:runtime-mac}

The operator installs a forbid-only policy during trusted bootstrap, or provisions
\path{mac.cedar} in the protected deployment policy directory. The runtime loads
and seals it before execution; there is no public replacement or uninstall API.
Every object authorization includes these forbids. Graph-local DAC can grant
candidate authority and local forbids can restrict it, but neither can omit the
operator policy. Controllers retain their boot policy until restart.

Execution admission checks the actual graph and dispatcher, including graphs
compiled before policy installation. With runtime MAC active, unsecured tools,
raw Pregel and remote execution, arbitrary Python nodes or branches, custom tool
wrappers, and enforcement waivers are refused. Supported paths use the object
broker or restricted in-process dispatcher. Thus extension does not imply
permission to bypass the mandatory boundary. Each independent interpreter must
load the policy. The controller, callbacks, and installed Python code remain
trusted; this is not a machine-wide LSM or protection against hostile bootstrap.

\subsection{Restricted in-process admission}

The high-level Cedar API admits an in-process tool only when supported source
analysis establishes $I\subseteq M$ and $I\subseteq A$, where $I$ overapproximates
its effects, $M$ is its manifest, and $A$ is the approved monitored API vocabulary.
Unknown calls, direct resource access, reflection, dynamic execution, unsupported
bodies, and unavailable source reject admission. Unused permissions are allowed:
the manifest is a ceiling, not a requirement to exercise every declaration.

Admission binds source to loaded code; dispatch rechecks callable and terminal
bindings. Monitored APIs enforce the surviving invocation grant, including
optional permissions removed by MAC. The certificate covers the admitted
function body, not earlier imports, decorators, dependency initialization, or
arbitrary Python. Those setup effects and API implementations remain trusted.
Untrusted implementations instead require confinement before import.

\subsection{Extensible semantic resources}
\label{sec:resources}

A resource class declares operations, object kind, trusted normalizer,
policy-visible attributes, enforcement locus, and lowering adapter. The registry
generates Cedar actions and entities; a closed manifest map can select among
declared operations without accepting an action name from the tool. Independent
inference systems can produce these manifests, but code analysis cannot decide
organizational entitlement. Reviewed principal policy supplies that authority.

A registered mediator assesses each canonical grant line as exact, stricter, or
unsupported and declares the host capabilities and protected paths it needs.
Activation establishes the resource boundary before tool import. Each broker
request is authenticated to its worker invocation and checked against the
surviving object, operation, and selector. Unsupported required authority or
ambiguous adapter ownership denies execution; unsupported optional lines and
their routes are removed. A handler's existence is not evidence of enforceability.

Typed resource contracts generate client methods, manifest effects, and backend
signature checks. The pump mediator distinguishes inspecting, setting flow, and
calibrating the same device even though every command traverses one socket.
The SQLite mediator keeps the database and its journal files outside worker
access and exposes only record read, write, and delete operations. Fixed
parameterized statements and a SQLite authorizer enforce its fixed schema;
workers cannot supply SQL. Unsupported triggers and schema changes fail closed.
This is an implemented record service, not arbitrary SQL authorization.

Mediators remain trusted reference monitors. They must honor the authorized
selector, validate payloads, bound I/O, and prevent alternate access. Protected
paths cannot overlap worker grants or runtime roots; operators must also exclude
aliases and hardlinks. A network-capable broker must classify its own operations
under mandatory policy. Naming a class \code{internet} does not automatically
classify every custom resource or disable coordinator networking.

\subsection{Exact grants and conservative lowering}

The immutable grant binds the principal, request, tool artifact, policy version,
rules, and operator-owned runtime baseline. A rule contains an action, semantic
selector, conditions, requirement identity, and provenance. The baseline makes
interpreter roots, tool packages, descriptors, environment, and protocol
channels visible authority rather than adapter entitlements.

Each enforcement obligation is assessed as \emph{exact}, \emph{tightened}, or
\emph{unsupported}. Tightening may remain \code{ENFORCED} when the requirement
ledger and all required obligations are satisfied. Unsupported obligations deny
unless the trusted caller explicitly selects an obligation marked waivable.
The current compiler marks only non-baseline \code{want} operation obligations
waivable; runtime-baseline needs and default-deny complements cannot be waived.
Waived identifiers enter the plan digest, and the receipt binds that plan and
records \code{DEGRADED}. This does not certify the complete original grant or
remove the remaining confinement. The bubblewrap invocation, object-broker, and sealed runtime-MAC paths
reject such waivers. Static checker waivers are separate review assumptions.

Host capabilities are probed for the selected adapter. The same declared policy
can be enforced exactly, conservatively tightened, explicitly degraded on a
supporting path, or denied on different hosts. A packaged runtime does not
supply a missing kernel mechanism. No adapter may replace an endpoint rule with
``network allowed'' or silently add a runtime dependency after policy.

\subsection{Activation receipts}

The coordinator creates a nonce and execution context. Before release, each
enforcer returns evidence covering its exact obligations. The receipt binds the
principal, request, artifact, grant, lowering result, worker identity,
mechanisms, host capabilities, and expiry. Missing, duplicate, additional,
stale, or digest-mismatched evidence fails verification.

A plan hash proves agreement about bytes. It does not prove that a filter was
installed on the process about to execute. The release barrier is the point
where intended authority becomes an enforced execution.

\section{Linux Enforcement}
\label{sec:linux}

The implementation retains two low-level Linux executors and adds a
high-level object-broker worker path. The namespace-free
\code{LandlockSandboxExecutor} uses Landlock for filesystem restrictions,
seccomp for syscall classes, cgroup v2 or rlimits for resources, and a supervisor
for lifetime~\cite{landlock,seccomp}. The separate
\code{LinuxSandboxExecutor} uses bubblewrap namespaces and seccomp and
integrates OSTree tool and runtime deployments~\cite{bubblewrap}. It requires
the namespace features used by its launcher. Supported authority, receipt
construction, and deployment integration must be reported per adapter.
The next two subsections describe the low-level Landlock executor. The
object-broker path independently activates Landlock and seccomp before import,
keeps a bound broker channel, and blocks direct sockets and process creation.
Evidence for one executor is not evidence for every path.

\subsection{Confinement before import}

A single-threaded trusted template starts without untrusted imports. For each
call, the parent resolves grant paths with \code{openat2} using
\code{RESOLVE\_BENEATH} and \code{RESOLVE\_NO\_MAGICLINKS}, constructs the
complete Landlock ruleset, optionally creates a fresh cgroup, and forks a worker.
The worker closes every non-protocol descriptor, sets \code{NoNewPrivs}, calls
\code{restrict\_self} on the one ruleset descriptor, installs seccomp and
limits, and only then imports the target. It never receives path descriptors or
root router authority.

The runtime baseline includes the interpreter, standard library, tool packages,
\code{/dev/urandom}, temporary storage, and protocol channels. These appear in
the grant and evidence. A missing baseline denies; the adapter cannot repair it
with ambient mounts or inherited descriptors.

\subsection{Kernel semantics}

Filesystem rules bind resolved kernel objects and access masks. The parent, not
the worker, constructs all rules. Create authority binds the resolved parent.
Tests exercise a granted file, a second file, direct raw \code{open(2)}, a
grandchild process, and \code{openat2} magic-link resolution.

Landlock network rules name ports, not endpoints. The phase-one seccomp profile
tightens network authority to no new \code{socket} or \code{connect}; endpoint
and name policy require a broker. Target-specific \code{EXECUTE} can be lowered
with Landlock, but phase one similarly tightens execution to none. Seccomp
returns \code{EPERM} for ordinary socket operations and kills the worker for
\code{ptrace}, process-VM reads, BPF, and namespace creation.

Delegated cgroup v2 controllers provide CPU, memory, PID limits, and
\code{cgroup.kill} descendant teardown. Without delegation, the receipt records
the representable rlimit and pidfd fallback. It never relabels an unavailable
physical-memory guarantee as exact. A supervisor owns wall time. If cancellation
cannot establish whether an irreversible effect committed or the worker died,
the outcome is \code{INDETERMINATE} and flow reservations remain durable.

\subsection{Versioned tool and runtime deployments}
\label{sec:deployments}

Flatpak separates application content from shared runtimes and uses OSTree to
store and distribute versioned filesystem trees~\cite{flatpak,ostree}.
\sys reuses this deployment model to identify the code admitted for a call.
A tool bundle contains an entrypoint, explicitly packaged dependencies,
read-only data, and a manifest in the same commit. A separate runtime commit
can contain the interpreter, standard library, loader, and native libraries.
This is a declaration and enforcement boundary: it does not infer policy or
discover every dependency arbitrary code may load.

For a manager-backed call, a trusted deployment manager resolves the selected
ref before policy preparation and records the exact commit against the
principal, session, tool, and call identity. The grant keeps the primary-file
digest and adds separate tool-deployment and runtime digests. Approval,
activation evidence, and audit bind the selected versions. Retry and
authenticated checkpoint recovery reuse the original selection while rerunning
the applicable security checks. New calls may resolve a moved channel.

The bubblewrap adapter mounts validated checkouts read-only and starts the
selected runtime interpreter. In packaged-runtime mode it does not mount host
\path{/usr}, \path{/lib}, or \path{/lib64}. The trusted worker shim remains
separately pinned operator code. These bindings are not yet integrated into
\code{LandlockSandboxExecutor}; its namespace-free path must not inherit the
deployment path's claims or measurements.

The manager also implements publisher-verified pulls, durable invocation
references, and execution leases. These are mechanisms requiring further
lifecycle validation, not evidence of complete deployment integrity. Current
review priorities include separating mutable channel names from release names,
making database-only retained commits visible to OSTree pruning, and requiring
a manager or an explicit operator-retention contract for static deployment
specifications. Read-only worker mounts do not protect a store writable by a
malicious process with the manager's host identity.

\section{Security Argument}
\label{sec:argument}

This is a conditional design argument for an \code{ENFORCED} operation. It
assumes correct placement, effective-object binding by every downstream
adapter, and verified host evidence, in addition to the TCB and mechanism
semantics in Section~\ref{sec:gap}. A router certificate alone does not
discharge those composition assumptions.

\paragraph{No policy grant path.}
For a fixed principal, candidate, policy version, and relevant context, owner
and principal/share policy construct candidate lines and mandatory policy can
only restrict them. Preparation and delegation require semantic subset checks.
A changed context requires fresh authorization; module order or a transform
cannot itself add authority to the original candidate.

\paragraph{No silent lowering expansion.}
Every semantic rule and baseline line has exactly one enforcement disposition.
Exact and tightened lowerings represent subsets of the grant. Unsupported
required obligations deny; an eligible explicit waiver produces a degraded
receipt outside the complete grant-subset claim. Therefore a
verified enforced receipt cannot silently retain broader authority in an owned
domain.

\paragraph{Worker authority is bound before execution.}
The selected backend must complete descriptor cleanup and its confinement
setup before untrusted import. The Landlock and bubblewrap paths use different
activation implementations and require separate evidence. The enforced contract
binds the observed worker to the request and grant before the release barrier;
ordinary worker output cannot substitute for setup evidence.

\paragraph{Framework effects remain mediated.}
For a certified router path, dispatch consumes authorization for the same
principal and immutable request. State, model, and output effects require their
own operations; authorization for tool invocation does not authorize them.

Under these assumptions, exact and tightened enforcement support
Equation~\ref{eq:effect} for the covered routes and host authority domains.
This subset relation does not guarantee useful execution or successful
completion. The current component evidence does not establish the assumptions
for every adapter or upstream path, and is not a whole-system theorem.

\section{Evaluation}
\label{sec:evaluation}

We ask three questions:

\begin{itemize}
  \item \textbf{RQ1:} Does the effect gap arise in executable agent tools?
  \item \textbf{RQ2:} What portion of the layered boundary has concrete
  implementation evidence, and what remains open?
  \item \textbf{RQ3:} What is the cost of framework policy mediation?
\end{itemize}

The implementation is based on LangGraph 1.2.12. The current design
baseline is WIP \code{40e24e9}. Earlier component evidence was
recorded against \code{53c5d317} and other snapshots; each experiment retains its revision,
hardware, and dependency identities. We separate dynamic canaries, bounded
source certificates, API conformance, kernel integration, and projections. No
projection is reported as runtime blocking evidence.

\subsection{RQ1: Executable effect-gap canaries}

We built eight deliberately vulnerable tools: file read, file write, shell,
SQL, fetch, email, Slack, and delegation. Each receives a policy-conformant call
but resolves or expands authority below the checked interface. Calls were
generated once by local Qwen3-8B at temperature zero and replayed identically.
Experiments use temporary directories, synthetic records, and loopback services;
no third-party deployment is attacked.

All eight unauthorized sinks were reached with no defense and after Progent
approved the policy-conformant calls. The same eight were reached behind each of
three tested generic LangChain wrappers (Eydii, Forge, and Nuggets). Here Forge
is the pinned \code{langchain-forge} 0.2.0 distribution, not the separately
reviewed FORGE/SASY framework in Table~\ref{tab:boundaries}. This result
does not show that their call policies are incorrect. It demonstrates precisely
the distinction in Equation~\ref{eq:effect}: approving the request does not
confine its implementation.

CaMeL addresses a stronger data-flow model. Under a generous assumption that all
relevant values remain untrusted-tagged, our static model marks all eight paths
covered. We separately reproduced one narrower post-validation case in which a
value trusted at the policy boundary became an absolute path during resolution.
That 1/1 result is not a general bypass claim against CaMeL.

\section{Limitations}
\label{sec:limitations}

\paragraph{Placement is incomplete.}
Adapters exist for the framework objects in Table~\ref{tab:objects}, but several
general graph, state, checkpoint, completion-callback, and publication paths
are not automatically routed. Direct Store references and legacy in-process
compatibility paths remain outside the composed claim. Restricted in-process
admission covers only its supported function bodies and monitored terminals.

\paragraph{Deployment integrity has a separate boundary.}
Version selection covers declared packaged contents, not inferred dependency
closure, reproducible builds, or every input a tool might interpret as code.
The operator must protect the store and separately trusted worker. Manager-free
static specifications and incomplete pruning integration cannot carry the same
automatic-retention claim as a fully validated manager-backed lifecycle.
Deployment integration with Landlock remains open.

\paragraph{Resource semantics remain adapter-specific.}
The SQLite mediator supports its fixed record schema, not arbitrary queries or
existing applications without adaptation. Pump and custom-resource backends
remain trusted. Mail, cloud, and endpoint-scoped networking require suitable
mediators; unsupported required grants deny rather than acquiring broad access.

\paragraph{Analysis coverage and accuracy are separate.}
Provenance tracks instrumented data and control dependencies, not arbitrary
native effects. Unadapted provider callbacks, state transformations, and caches
can lie outside tracking. Trusted read bounds must include baseline authority;
labels on a return value cannot undo an earlier side effect. Classifier errors
remain possible, and analysis is disabled unless configured. Analyzer plugins
are trusted Python; a timed-out thread cannot be forcibly terminated, although
its late findings cannot commit.

\paragraph{Mandatory scope is explicit.}
Sealed operator policy governs supported execution in one interpreter. Each
controller must load it. Trusted code can still access the coordinator's host
authority, so privileged brokers and callbacks must honor their contracts.
Runtime MAC rejects unsupported graph shapes; this reduces compatibility and
does not establish complete mediation for every LangGraph program.

\paragraph{Evidence is local and software-rooted.}
Receipts do not protect against a compromised kernel, launcher, policy backend,
canonicalizer, label provider, or trusted module. The router analyzer is trusted
and has regression tests, not a machine-checked soundness proof. Landlock
constrains access to live objects; it does not provide snapshot integrity.

\paragraph{Evaluation is not yet complete.}
The canary suite is small and synthetic. Dynamic \sys rows for AgentDojo,
InjecAgent, and ASB, comparative resource-broker experiments, and fresh-worker latency remain
necessary before making broad utility or deployment claims.

\section{Related Work}

\paragraph{Agent privilege and information flow.}
Progent combines tool-call policies with policy generation and checked
updates~\cite{progent}. CaMeL separates trusted control from untrusted data;
SEAgent applies mandatory policy to agent interactions~\cite{camel,seagent}.
FORGE exposes a reference monitor with provenance and instrumentation~\cite{forgecode}.
These systems provide real enforcement and extension interfaces. Our narrower
focus is preserving invocation resource authority across native tools, domain
resources, and framework flows. \sys supplies conservative provenance and a
fixed-policy extension contract, not their policy generators or full interpreters.

\paragraph{Agent sandboxes and policy composition.}
APF combines Cedar grants and control forbids, and projects authored sandbox
policy through enforcement adapters~\cite{apf}. Nono supplies caller-sensitive
command sandboxes and protocol mediation; Sandlock confines local MCP tools from
capability declarations~\cite{nono,sandlock}. Thus neither DAC/MAC composition
nor host-dependent lowering is unique to \sys. We connect manifest requirements,
principal authorization, and mandatory restrictions to one enforced invocation
grant, with typed domain mediators and a sealed runtime policy boundary.
Table~\ref{tab:boundaries} identifies the scoped differences and trust assumptions.

\paragraph{Agent-security evaluation.}
AgentDojo provides stateful tasks and indirect-prompt-injection security
cases~\cite{agentdojo}. InjecAgent contains 1,054 cases over user and attacker
tools~\cite{injecagent}; ASB spans multiple attack classes, scenarios, and
hundreds of tools~\cite{asb}. These benchmarks primarily measure behavioral
attack success and utility. Our canaries isolate whether an admitted
implementation retains unauthorized authority; the questions are complementary.

\paragraph{Reference monitors and hook placement.}
LSM separates fixed mediation hooks from policy, preserves discretionary checks,
and supports restrictive module composition~\cite{wright2002lsm,linuxlsm}.
SELinux user-space object managers extend the same architecture beyond kernel
objects~\cite{selinuxnotebook,sepgsql}. Prior work shows that authorization-hook
placement itself requires systematic analysis~\cite{zhang2002cqual}. \sys
adapts these ideas to framework objects and agent execution paths.

\paragraph{Flatpak deployments and portals.}
Flatpak provides application/runtime separation, versioned distribution, and
mediated host access through portals~\cite{flatpak,ostree,portals}.
Our deployment-backed adapter reuses OSTree and bubblewrap. The agent-specific
work is connecting selected code to principal/request authorization, approval,
activation evidence, and durable retry and checkpoint identity. Portal guidance
on validated requests and trusted resource handles also informs future broker
operations; a general desktop-portal integration is not implemented.

\paragraph{Sandboxing and authorization.}
Landlock provides unprivileged, monotonic restriction over filesystem and port
objects~\cite{landlock}; seccomp restricts syscall classes~\cite{seccomp}. Cedar
provides typed principal--action--resource--context policies with forbid-overrides
composition~\cite{cedar}. \sys uses Cedar for authorization and Linux mechanisms
for enforcement; neither is asked to model the other's domain.

\section{Conclusion}

A correct call decision does not bound every effect of the admitted tool.
\sys connects resource requirements to invocation grants and carries those
grants through restricted APIs, domain mediators, and host confinement.
Replaceable analyses supply evidence to fixed policies; local configurations
cannot remove an installed mandatory ceiling. The implementation adds concrete
resource and provenance mechanisms while retaining explicit trust and coverage
limits. Whole-framework mediation and comparative end-to-end evaluation remain
obligations beyond the component evidence reported here.

\section{Ethical Considerations}

The bypass canaries target deliberately vulnerable tools in temporary
directories, synthetic databases, and loopback services. They do not probe or
modify third-party deployments. Canary values are fake and audit logs hash
arguments by default.

A security framework can create false confidence when its placement or host
support is incomplete. \sys mitigates that risk by denying unsupported grants,
stamping waivers as degraded, publishing the protected-operation inventory, and
separating component evidence from system claims. Operators remain responsible
for policy correctness, TCB maintenance, user notice, and recovery from
\code{INDETERMINATE} operations.
