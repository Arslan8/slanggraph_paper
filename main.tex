\begin{abstract}
An agent policy is useful only if an approved tool cannot exceed it. Tool-call
checks leave native effects unchecked; file sandboxes cannot distinguish records
in one database. Connecting these boundaries is especially difficult when tool
requirements come from fallible inference and execution spans runtime APIs,
native processes, and resource services.
We present \sys, an extensible enforcement framework for LangGraph. Manifests
propose requirements, principal policies authorize them, and sealed operator
policy caps the resulting invocation grant. Adapters assess each obligation as
exact, tightened, or unsupported and compose runtime checks, semantic brokers,
and host confinement around that grant. Unlike APF's projection of authored
sandbox policies, \sys binds manifest-derived invocation authority to both
domain operations and tool execution. New requirement producers reuse this
boundary without becoming its enforcement mechanism.
In a Pandas integration, call authorization leaves three forbidden filesystem
effects reachable; host enforcement removes all three while preserving the
computation. A separate 49-case census exposes a metadata-access difference
between Landlock and container adapters. With a common Cedar authorizer, these
host adapters take $3.62$--$8.37\times$ the admitted in-process path on five
small workloads. An opaque two-binary chain executes under confinement but is
rejected by source admission, demonstrating why both paths are needed.
\end{abstract}

\section{Introduction}

Agentic systems build and deploy software~\cite{replitagent}, analyze
databases~\cite{aidatascienceteam}, conduct document
research~\cite{opennotebook}, and automate browser tasks~\cite{browseruse}.
They turn model outputs into operations using their users' files, credentials,
and service connections, making mistakes and adversarial instructions consequential.

The consequences are already concrete. In 2025, SaaStr reported that Replit
Agent deleted its production database and disregarded code-freeze
instructions~\cite{saastrincident}. Amazon attributed a December 2025 Cost
Explorer interruption in one region, discussed in its Kiro incident response,
to misconfigured access controls~\cite{awscostincident}. Sandboxing alone also
requires careful integration: Anthropic disclosed and patched Claude Code
escapes through configuration-file injection and Git worktree path confusion
in 2026~\cite{claudeconfigescape,claudeworktreeescape}. These cases motivate
enforceable limits on an agent's effects, independent of whether the model
follows instructions.

The same boundary problem appears without a model mistake. In our controlled
canary study, eight policy-conformant calls pass Progent and still reach
unauthorized sinks inside deliberately vulnerable tool implementations
(Section~\ref{sec:effect-gap}). Approving the declared request does not remove
the implementation's ambient authority.

Existing defenses address this problem at several boundaries. Progent and OPA
authorize tool calls~\cite{progent,opatools}. CaMeL, SEAgent, and FORGE enforce
policies over interpreted execution, agent interactions, or tracked information
flows~\cite{camel,seagent,forge}. FIDES tracks confidentiality and integrity;
IsolateGPT isolates applications and mediates their collaboration through user
permissions~\cite{fides,isolategpt}. Nono and Sandlock confine tool processes
using declared capabilities~\cite{nono,sandlock}. NVIDIA's Agent Policy Fabric
(APF) combines programmable grants and mandatory forbids with enforcement
adapters~\cite{apf}. These mechanisms provide useful enforcement, but at
different scopes.

The remaining gaps appear when execution crosses those scopes. A tool-call
proxy checks the requested operation, while an approved native implementation
can perform additional accesses~\cite{progent,opatools}. CaMeL's restricted
interpreter does not confine its native callees; SDK and event-level mediation
likewise depends on the tool implementation respecting the instrumented
boundary~\cite{camel,seagent,forge}. Host sandboxes constrain files and
processes, but a database-file permission cannot distinguish Alice's record
from Bob's~\cite{nono,sandlock}. APF supplies policy-to-sandbox projection, but
its reviewed integration does not bind manifest-derived invocation authority
to domain mediators and framework operations through one enforcement
contract~\cite{apf,apfprojection}. Table~\ref{tab:features} identifies these gaps. Improving
policy inference alone does not close them.

Deployment diversity makes this gap harder to close. An agent's tool may be
(1) a function implemented entirely inside the framework
runtime~\cite{langchaintools}, (2) a shim controlling a companion Chrome process
through Playwright~\cite{playwrightbrowser}, or (3) an MCP client sending
requests to a local or remote tool server~\cite{mcparchitecture}.
Browser agents themselves can run locally or use cloud-hosted
browsers~\cite{browseruse}. Runtime checks cannot alone restrict a companion or remote server; client
confinement cannot express all service operations. A deployable defense must
adapt to the tool configuration and host environment.

The missing abstraction is a resource authority contract that survives these
transitions. Requirements must remain proposals capped by principal and operator
policy. Lowering must expose whether the actual host can enforce each obligation,
including required tightening or refusal. Finally, a record permission must bind
both the broker check and the worker's inability to bypass it. Independent
allowlists do not establish that relationship.

To this end, we design \sys, an extensible security enforcement framework for
LangGraph. Following Flask's separation of a security server from enforcing
object managers~\cite{spencer1999flask}, \sys constructs one invocation grant
from manifests, principal authorization, and sealed operator restrictions.
Framework object managers, domain mediators, and host adapters enforce its
obligations. Admitted in-process tools use monitored APIs; untrusted native
tools execute in confined workers. This is composite distributed reference
monitoring across cooperating enforcement components. Remote services still
require trusted enforcement at their own resource boundary.

APF already projects authored sandbox policies and supplies mandatory forbids.
\sys's additional contract derives authority for each invocation and carries
it through domain mediation, source admission, and host activation with an
explicit fidelity ledger. Like EC's separation of compartment identification
from ECK enforcement~\cite{khan2023ec}, and LSM's separation of hooks from
policy~\cite{wright2002lsm}, this design lets new requirement producers reuse
enforcement. Producer output may be untrusted data; installed policy engines,
analyzer code, and mediators remain trusted components.

Our evaluation demonstrates why both call and effect checks are necessary.
Host enforcement removes three forbidden Pandas effects that call authorization
leaves reachable. A separate census retains all 30 allowed-control trials per
adapter while exposing a Landlock metadata case. With the same Cedar authorizer,
Landlock and container evaluation adapters take $3.62$--$4.92\times$ and
$5.98$--$8.37\times$ admitted in-process runtime. Conversely, an opaque native
chain runs under confinement even though source admission rejects it. The
earlier protected application replay takes $3.48\times$ upstream runtime;
full-workflow time is $1.20\times$, including model and runner effects.

\section{Motivation}
\label{sec:gap}

Consider a reporting agent authorized to read Alice's record and send a summary
to an internal audience. Its tool accepts \code{record=alice}, passes a call
policy, and then reads Bob's record from the same database. A file sandbox still
allows this access if it grants the database file. Even a correct read can
violate policy if the summary later reaches an unauthorized external model.
This example exposes three requirements for an enforcement framework.

\subsection{One policy across execution boundaries}

The policy concerns a record and a destination, not a tool name or database
pathname. \sys represents those permissions independently of execution placement.
A manifest proposes requirements; principal policies authorize them; mandatory
policy restricts the result. The resulting grant is the authority ceiling for
the invocation. Omitting Bob's record from a manifest does not hide an access
from enforcement, and declaring it does not make it authorized. Independent
inference systems can therefore propose requirements without becoming the
mechanism that constrains tool effects.

\subsection{Lowering that follows the deployment}

An admitted runtime implementation can use a grant-checked record API. A native
worker needs a broker for that API and host controls preventing direct database
access. These are different realizations of the same permission. A filesystem
sandbox alone is too coarse; denying the database entirely also prevents the
legitimate read. \sys's SQLite mediator checks record operations, while the
host adapter protects the database directory and broker channel. The pump
mediator similarly distinguishes device operations that share one socket.
Adapters assess the concrete grant and host capabilities. Missing a required
mechanism prevents execution instead of silently broadening the permission.

\subsection{Monitors that compose without an escape path}

The database check must remain effective when the worker tries another API,
and output restrictions must survive the tool's return. \sys composes host
bypass prevention, authenticated broker requests, per-operation grant checks,
and provenance-aware checks at instrumented framework boundaries. These checks
share invocation authority rather than independent allowlists.
Operator policy is sealed outside graph-local configuration, so a helper or
local override cannot remove it on a supported path. This differs from nono's
per-intercept replacement of base sandbox permissions~\cite{nono}; APF already
provides mandatory forbids, but does not supply the shared domain and runtime
grant contract~\cite{apf}. The mandatory scope is the configured interpreter
and its trusted adapters (Section~\ref{sec:model}), not an unmodified remote
server. New analyzers and resource mediators reuse this enforcement contract
instead of reconstructing the security boundary for each defense.

\section{Security Model}
\label{sec:model}

Let $c=(p,t,a,h)$ denote a call with authenticated principal $p$, tool $t$,
arguments $a$, and security history $h$. Let $R(c)$ be the canonical candidate
authority proposed by its manifest together with the explicit runtime baseline.
Discretionary authorization and mandatory filtering produce grant $G(c)$;
lowering produces effective authority $L_{B,H}(c)$ for boundary $B$ and host $H$.
For an \code{ENFORCED} invocation, the monotonic-authority invariant is
\begin{equation}
  E_{B,H}(c) \subseteq L_{B,H}(c) \subseteq G(c) \subseteq R(c),
  \label{eq:effect}
\end{equation}
where $E$ is the set of reachable effects projected onto the protected domains.
Every tool-requested line of $G$ must satisfy principal and owner ceilings and
survive mandatory forbids; the runtime baseline is operator-approved.
Equation~\ref{eq:effect} is a conditional enforcement
obligation, not a claim that finite tests establish every reachable effect.

\subsection{Reference-monitor requirements}

Following EC's Embedded Compartmentalizer Kernel (ECK), we organize enforcement
around complete mediation, tamperproofness, and verifiability~\cite{khan2023ec}.
These are the classical
reference-monitor obligations~\cite{anderson1972reference,jaeger2011reference};
here they apply across the agent runtime and its execution backends.

\paragraph{G1: Complete mediation.}
For an admitted deployment, every operation in its protected inventory must
reach a refusing check before its effect. The supported contract includes the
admitted tool path and the framework/model/output routes declared for that
deployment. Runtime MAC rejects unsupported graph shapes rather than granting
them this guarantee. A missing hook on a declared protected path is a coverage
failure, not a reason to redefine scope. General LangGraph compatibility paths
remain outside the established contract (Section~\ref{sec:limitations}).

\paragraph{G2: Tamperproofness.}
Code outside the TCB must not modify the monitor, policy, grants, provenance, or
confinement configuration. \sys separates hostile native code from the
coordinator and admits in-process tool bodies only under a restricted API
contract. Bootstrap code and resource mediators remain trusted.

\paragraph{G3: Verifiability.}
The enforcement mechanism must be sufficiently bounded and explicit to support
systematic analysis of G1, G2, and authorization correctness. \sys exposes
dispatch and adapter contracts for this purpose;
Section~\ref{sec:evaluation} reports the current component checks. Activation
receipts bind a worker to enforced mechanisms, but do not prove monitor
correctness.

\paragraph{Monotonic authority under composition.}
We additionally require that preparation, delegation, policy modules, and
lowering preserve or reduce authority. An unsupported required obligation
denies. Explicit waivers are limited to obligations eligible for degradation;
they do not waive identity binding, default deny, or isolation before import.
Degraded executions do not carry the complete grant-subset claim. The
sealed runtime-MAC path rejects enforcement waivers entirely.

\subsection{Threat model}

The adversary controls model outputs, retrieved data, tool arguments, untrusted
tool and node code, dependencies loaded after confinement, and subagent prompts.
It may exploit retries, argument rewriting, path races, import side effects,
malformed results, resource exhaustion, cancellation, and stale checkpoints.

The framework TCB contains authentication, the coordinator and router, policy
backend, modules, canonicalizers, grant compiler, framework adapters, audit and
flow stores, and operator-promoted trusted nodes. The host TCB contains the
kernel, launcher, enforcement adapter, and supervisor. In deployment mode, the
deployment manager, its protected store, and approved runtime publishers also
belong to the TCB. Kernel compromise, side
channels, denial of service, and a provider's handling of data after authorized
submission are outside the claim. Trusted initialization and mediator code are
not confined by a tool-body certificate. Task intent is also separate: exact authority does not
prove that an allowed action is beneficial.
This boundary puts credential custody, entitlement, and enforcement under
operator control while treating generated requests and confined implementations
as hostile. An untrusted requirement producer submits data through the manifest
interface; installing its Python code as an analyzer would instead add it to
the TCB. A mediated service is trusted for its resource semantics and must be
protected from direct worker access.

\section{Design Overview}
\label{sec:overview}

\subsection{LangGraph background}

LangGraph represents an application as nodes operating on shared state and
edges selecting subsequent work~\cite{langgraphapi}. Nodes may call models,
invoke tools, update state, or launch subgraphs. \code{ToolNode} executes tool
calls requested by the model; it is one dispatch surface, not the entire
application. Compilation produces a Pregel runtime that schedules work in
steps, including parallel branches~\cite{langgraphpregel}. Checkpointers save
execution state for resume, while stores retain data across
interactions~\cite{langgraphpersistence}. Consequently, a tool return can later
reach a model prompt, checkpoint, or outward publication. Retrying or restoring
work must preserve identity and rerun the applicable authorization checks.

\subsection{Components and execution paths}

Figure~\ref{fig:architecture} separates responsibilities. The \emph{router}
(\code{HostRouter}) intercepts protected framework operations. The
\emph{authorizer} computes grants; the \emph{coordinator} negotiates obligations
and validates activation. An \emph{object manager} enforces framework operations.
The \emph{dispatcher} selects in-process or worker execution. Its
\emph{object broker} authenticates worker requests and invokes a trusted
\emph{resource mediator}, such as the SQLite record service. Host adapters
constrain effects outside those APIs.

There are three production Linux paths. \code{LandlockSandboxExecutor} provides
namespace-free filesystem/syscall confinement; \code{LinuxSandboxExecutor}
uses bubblewrap and supports versioned deployments; \code{ObjectBrokerDispatcher}
composes a separate Landlock worker with semantic mediators. The protected
Pandas experiment uses the bubblewrap path. The new Landlock/rootless-container
timings use evaluation adapters around a common authorizer, not these production
executors. Their telemetry is distinct from production activation receipts.

\subsection{Scope and authority}

The protected inventory is independent of hook placement. It covers principal
transfer, tool and child dispatch, registry changes, state/store access,
approval resume, explicitly guarded framework operations, model prompts,
output publication, and host resources. A missing refusing route is a coverage
failure. \code{ToolNode} and \code{guarded\_tool} are clients of the router,
not independent reference monitors.

Authorization determines the grant; adapters make other authority unavailable;
activation evidence binds those controls to the actual execution. A policy
decision or an adapter capability name alone cannot establish all three.

\section{Framework Object Manager}
\label{sec:objects}

\subsection{Single-path dispatch}

\code{HostRouter} is the sole protected dispatch entry on router-mediated
framework paths; resource tools use the authorizer/dispatcher contract.
Sync and async APIs share these contracts. Every physical retry
receives a fresh request and decision; this matters because LangGraph wrappers
may call their \code{execute} continuation repeatedly with changed arguments.
Mediation outside that continuation would authorize one request and execute
another.

Child dispatch always runs credential-transfer policy and an explicit subset
check, including same-principal branches. The audit therefore records identity
transfers instead of treating them as invisible no-ops. A worker may request a
nested tool only over an authenticated channel bound by the host; caller-supplied
tool names and principal fields do not establish origin.

\subsection{State, checkpoints, model input, and output}

Per-call confinement alone cannot prevent cross-call exfiltration. The object
manager therefore mediates the paths that carry data between calls:

\paragraph{State and store.}
Keys have owners and labels. Tools receive only declared state channels and a
mediated store interface. State writes and reads are separate operations so
mandatory policy can constrain both provenance and use.

\paragraph{Checkpoints.}
Restore verifies a keyed hash chain, predecessor, monotone sequence, and
principal binding. A valid serialized shape is not sufficient: replay and
cross-principal substitution are rejected.

\paragraph{Model invocation.}
Policy runs before prompt assembly and may deny or strip labeled values. This is
the last framework boundary before data reaches the model-provider channel.

\paragraph{Output.}
Policy sees content labels, destination clearance, and the proposed effect. Its
verdict is allow, deny, redact, or escalate. Tool post-processing and output
mediation are distinct; a safe return value may still target an unsafe
destination.

\subsection{Cross-call flow scheduling}

Operators may configure a coarse session label in addition to per-operation
authorization. Each possible read has a conservative source label; each outward
effect may have a sink ceiling. Before parallel fan-out, source labels join into
durable session state. A sink proceeds only when the accumulated label is below
its ceiling. Reservations span execution, post hooks, audit, and confirmed
worker termination, preventing a sink from racing a concurrent source.

Session reservations are distinct from the provenance runtime below. Their
soundness requires conservative read bounds, including runtime-baseline and
degraded authority, and mediation of outward channels. Unknown effective
authority cannot be assigned a public label.

\subsection{Replaceable analysis under fixed policy}
\label{sec:analysis}

The analysis runtime supplies a registry, dependency scheduler, canonical store,
provenance, and scoped query interface. Plugins return findings and restrictive
annotations; the schema rejects policy, rule, and grant fields. Security modules
interpret that evidence under a configuration fixed before execution. Approval
cannot override another module's denial.

Required analyzers finish before the protected operation. Exceptions or deadlines
produce unavailable evidence, so required-analysis gates deny. Late findings
cannot commit. Every physical attempt binds a fresh snapshot to principal,
session, normalized and actual arguments, invocation, and execution identity.
Historical findings cannot authorize a new attempt.

Provenance identifies immutable value versions and records data/control
dependencies. Confidentiality and risk labels join; allowed-reader sets
intersect. Opaque transformations retain declared influences, and model outputs
inherit submitted context. Plugins may add restrictions and ancestry, not
remove them. Trusted interpreter adapters may supply more precise dependencies.
\code{AnalysisFlowPolicy} checks tools, model destinations, and output using
these labels and trusted read bounds; no declassification API is enabled.

SQLite transactions persist findings and provenance. Authenticated checkpoints
bind policy, domain, and role configuration. This provides a stable enforcement
interface for new analyses, not a proof of detector accuracy. Analyzer and
adapter code remains trusted, and required coverage must be declared. Unadapted
callbacks, reducers, caches, and custom nodes require adapters or refusal.

\subsection{Certifying router placement}

The router certificate is a bounded, path-sensitive authorization-state
analysis over Python ASTs. It tracks a successful decision's permission class,
principal identity, request identity, and single-use dispatch obligation.
Changed objects, repeated dispatch, unknown calls, unsupported statements, and
path-budget exhaustion remain unresolved. Reviewed helper contracts are
source-hash bound so implementation drift invalidates dependent obligations.

This analysis does not prove Python semantics or policy correctness. It provides
reviewable evidence for a finite router boundary. The protected-operation
inventory is maintained separately, ensuring that a missing path cannot
disappear merely because the checker did not certify it.

\section{From Policy to Enforced Grant}
\label{sec:grant}

\subsection{Constructive DAC, restrictive MAC}

A tool profile proposes finite authority. The tool owner and invoking principal
must both permit each candidate line; explicit shares may contribute delegated
authority. Undeclared tools receive no resource or caller authority. A required
\code{need} line that does not survive denies the operation; an optional
\code{want} line is removed.

Mandatory modules run after discretionary construction and may emit only
forbids, labels, or a restrictive verdict. They cannot introduce a permit or
mutate the candidate. The object authorizer checks the generated owner ceiling and principal/share
permits, then tests each candidate against operator and local forbids. Any schema,
validation, evaluation, or diagnostic failure denies~\cite{cedar}.

Preparation is a separate trusted operation. Its output is normalized and
reauthorized; a resource-changing transform must prove semantic attenuation over
typed actions and selectors. String length, structural similarity, and module
trust are not authority orderings.

\paragraph{Alice's record.}
Figure~\ref{fig:record-contract} makes the proposal/authority distinction concrete.
For \code{operation=read}, the closed manifest map selects only the read action.
Alice's policy admits \code{notes/alice}; replacing the argument with
\code{notes/bob} removes the required line and denies before dispatch.
A broader manifest still cannot supply Alice with Bob's entitlement. If sealed
MAC forbids the surviving read, a local permit cannot restore it. A worker that
requests Bob's record after authorization fails the broker's per-operation
grant check; opening the database directly must fail at the host boundary.

\subsection{A mandatory ceiling across local configurations}
\label{sec:runtime-mac}

The operator installs a forbid-only policy during trusted bootstrap, or provisions
\path{mac.cedar} in the protected deployment policy directory. The runtime loads
and seals it before execution; there is no public replacement or uninstall API.
Every object authorization includes these forbids. Graph-local DAC can grant
candidate authority and local forbids can restrict it, but neither can omit the
operator policy. Controllers retain their boot policy until restart.

Execution admission checks the actual graph and dispatcher, including graphs
compiled before policy installation. With runtime MAC active, unsecured tools,
raw Pregel and remote execution, arbitrary Python nodes or branches, custom tool
wrappers, and enforcement waivers are refused. Supported paths use the object
broker or restricted in-process dispatcher. Thus extension does not imply
permission to bypass the mandatory boundary. Each independent interpreter must
load the policy. The controller, callbacks, and installed Python code remain
trusted; this is not a machine-wide LSM or protection against hostile bootstrap.

\subsection{Restricted in-process admission}

The high-level Cedar API admits an in-process tool only when supported source
analysis establishes $I\subseteq M$ and $I\subseteq A$, where $I$ overapproximates
its effects, $M$ is its manifest, and $A$ is the approved monitored API vocabulary.
Unknown calls, direct resource access, reflection, dynamic execution, unsupported
bodies, and unavailable source reject admission. Unused permissions are allowed:
the manifest is a ceiling, not a requirement to exercise every declaration.

Admission binds source to loaded code; dispatch rechecks callable and terminal
bindings. Monitored APIs enforce the surviving invocation grant, including
optional permissions removed by MAC. The certificate covers the admitted
function body, not earlier imports, decorators, dependency initialization, or
arbitrary Python. Those setup effects and API implementations remain trusted.
Untrusted implementations instead require confinement before import.

\subsection{Extensible semantic resources}
\label{sec:resources}

A resource class declares operations, object kind, trusted normalizer,
policy-visible attributes, enforcement locus, and lowering adapter. The registry
generates Cedar actions and entities; a closed manifest map can select among
declared operations without accepting an action name from the tool. Independent
inference systems can produce these manifests, but code analysis cannot decide
organizational entitlement. Reviewed principal policy supplies that authority.

A registered mediator assesses each canonical grant line as exact, stricter, or
unsupported and declares the host capabilities and protected paths it needs.
Activation establishes the resource boundary before tool import. Each broker
request is authenticated to its worker invocation and checked against the
surviving object, operation, and selector. Unsupported required authority or
ambiguous adapter ownership denies execution; unsupported optional lines and
their routes are removed. A handler's existence is not evidence of enforceability. For Alice's read,
the SQLite mediator supplies the record check only if the host prevents direct
database access and the broker channel binds requests to her invocation. Losing
either dependency makes that required read unsupported.

Typed resource contracts generate client methods, manifest effects, and backend
signature checks. The pump demo models a fluid pump through a local Unix-socket service. Inspect
reads device state, set-flow changes its rate, and calibrate changes calibration;
all use the same socket. The mediator distinguishes these operations when a
socket allowlist cannot. The simulator itself does not enforce authorization.
The SQLite mediator keeps the database and its journal files outside worker
access and exposes only record read, write, and delete operations. Fixed
parameterized statements and a SQLite authorizer enforce its fixed schema;
workers cannot supply SQL. Unsupported triggers and schema changes fail closed.
This is an implemented record service, not arbitrary SQL authorization.

Mediators remain trusted reference monitors. They must honor the authorized
selector, validate payloads, bound I/O, and prevent alternate access. Protected
paths cannot overlap worker grants or runtime roots; operators must also exclude
aliases and hardlinks. A network-capable broker must classify its own operations
under mandatory policy. Naming a class \code{internet} does not automatically
classify every custom resource or disable coordinator networking.

\subsection{Exact grants and conservative lowering}

The immutable grant binds the principal, request, tool artifact, policy version,
rules, and operator-owned runtime baseline. A rule contains an action, semantic
selector, conditions, requirement identity, and provenance. The baseline makes
interpreter roots, tool packages, descriptors, environment, and protocol
channels visible authority rather than adapter entitlements.

Each enforcement obligation is assessed as \emph{exact}, \emph{tightened}, or
\emph{unsupported}. Tightening may remain \code{ENFORCED} when the requirement
ledger and all required obligations are satisfied. Unsupported obligations deny
unless the trusted caller explicitly selects an obligation marked waivable.
The current compiler marks only non-baseline \code{want} operation obligations
waivable; runtime-baseline needs and default-deny complements cannot be waived.
Waived identifiers enter the plan digest, and the receipt binds that plan and
records \code{DEGRADED}. This does not certify the complete original grant or
remove the remaining confinement. The bubblewrap invocation, object-broker, and sealed runtime-MAC paths
reject such waivers. Static checker waivers are separate review assumptions.

Host capabilities are probed for the selected adapter. The same declared policy
can be enforced exactly, conservatively tightened, explicitly degraded on a
supporting path, or denied on different hosts. A packaged runtime does not
supply a missing kernel mechanism. No adapter may replace an endpoint rule with
``network allowed'' or silently add a runtime dependency after policy.

\paragraph{Execution status.}
\code{ENFORCED} means all retained obligations passed activation and the
requirement ledger remains satisfiable. \code{DEGRADED} records an eligible,
explicitly waived obligation on a path that permits waivers; it carries no
complete grant-subset claim. \code{INDETERMINATE} is an outcome whose commit or
termination status cannot be established, not a weaker permission level.

\subsection{Activation receipts}

The coordinator creates a nonce and execution context. Before release, each
enforcer returns evidence covering its exact obligations. The receipt binds the
principal, request, artifact, grant, lowering result, worker identity,
mechanisms, host capabilities, and expiry. Missing, duplicate, additional,
stale, or digest-mismatched evidence fails verification.

A plan hash proves agreement about bytes. It does not prove that a filter was
installed on the process about to execute. The release barrier is the point
where intended authority becomes an enforced execution.

\section{Linux Enforcement}
\label{sec:linux}

The implementation retains two low-level Linux executors and adds a
high-level object-broker worker path. The namespace-free
\code{LandlockSandboxExecutor} uses Landlock for filesystem restrictions,
seccomp for syscall classes, cgroup v2 or rlimits for resources, and a supervisor
for lifetime~\cite{landlock,seccomp}. The separate
\code{LinuxSandboxExecutor} uses bubblewrap namespaces and seccomp and
integrates OSTree tool and runtime deployments~\cite{bubblewrap}. It requires
the namespace features used by its launcher. Supported authority, receipt
construction, and deployment integration must be reported per adapter.
The next two subsections describe the low-level Landlock executor. The
object-broker path independently activates Landlock and seccomp before import,
keeps a bound broker channel, and blocks direct sockets and process creation.
Evidence for one executor is not evidence for every path.

\subsection{Confinement before import}

A single-threaded trusted template starts without untrusted imports. For each
call, the parent resolves grant paths with \code{openat2} using
\code{RESOLVE\_BENEATH} and \code{RESOLVE\_NO\_MAGICLINKS}, constructs the
complete Landlock ruleset, optionally creates a fresh cgroup, and forks a worker.
The worker closes every non-protocol descriptor, sets \code{NoNewPrivs}, calls
\code{restrict\_self} on the one ruleset descriptor, installs seccomp and
limits, and only then imports the target. It never receives path descriptors or
root router authority.

The runtime baseline includes the interpreter, standard library, tool packages,
\code{/dev/urandom}, temporary storage, and protocol channels. These appear in
the grant and evidence. A missing baseline denies; the adapter cannot repair it
with ambient mounts or inherited descriptors.

\subsection{Kernel semantics}

Filesystem rules bind resolved kernel objects and access masks. The parent, not
the worker, constructs all rules. Create authority binds the resolved parent.
Tests exercise a granted file, a second file, direct raw \code{open(2)}, a
grandchild process, and \code{openat2} magic-link resolution.

Landlock network rules name ports, not endpoints. The phase-one seccomp profile
tightens network authority to no new \code{socket} or \code{connect}; endpoint
and name policy require a broker. Target-specific \code{EXECUTE} can be lowered
with Landlock, but phase one similarly tightens execution to none. Seccomp
returns \code{EPERM} for ordinary socket operations and kills the worker for
\code{ptrace}, process-VM reads, BPF, and namespace creation.

Delegated cgroup v2 controllers provide CPU, memory, PID limits, and
\code{cgroup.kill} descendant teardown. Without delegation, the receipt records
the representable rlimit and pidfd fallback. It never relabels an unavailable
physical-memory guarantee as exact. A supervisor owns wall time. If cancellation
cannot establish whether an irreversible effect committed or the worker died,
the outcome is \code{INDETERMINATE} and flow reservations remain durable.

\subsection{Versioned tool and runtime deployments}
\label{sec:deployments}

The bubblewrap path uses OSTree to bind a tool bundle and its runtime to
immutable commits~\cite{flatpak,ostree,bubblewrap}. The deployment manager resolves
versions before authorization; grants, approval, activation, and audit retain
those identities. Retries and authenticated checkpoint recovery reuse the
selection while rerunning security checks. Packaged-runtime execution mounts
the selected checkouts read-only rather than adding host interpreter directories.

This binds declared packaged code, not arbitrary dependency closure. The store,
runtime publisher, and pinned worker shim remain trusted. Invocation references
and leases support retention, with lifecycle limits recorded in
Appendix~\ref{app:component-evidence}. The namespace-free Landlock path has a
separate code-selection contract.

\section{Security Argument}
\label{sec:argument}

This is a conditional design argument for an \code{ENFORCED} operation. It
assumes correct placement, effective-object binding by every downstream
adapter, and verified host evidence, in addition to the TCB and mechanism
semantics in Section~\ref{sec:model}. A router certificate alone does not
discharge those composition assumptions.

\paragraph{Monotonic-authority invariant.}
For a fixed principal, candidate, policy version, and relevant context, owner
and principal/share policy construct candidate lines and mandatory policy can
only restrict them. Preparation and delegation require semantic subset checks.
A changed context requires fresh authorization; module order or a transform
cannot itself add authority to the original candidate. Thus authorization
establishes $G\subseteq R$. Conservative lowering establishes $L\subseteq G$;
complete mediation and correct enforcers establish $E\subseteq L$. Composition
preserves Equation~\ref{eq:effect} by transitivity. The trusted baseline is part
of $R$, so interpreter or broker dependencies cannot appear as unaccounted grants.

\paragraph{No silent lowering expansion.}
Every semantic rule and baseline line has exactly one enforcement disposition.
Exact and tightened lowerings represent subsets of the grant. Unsupported
required obligations deny; an eligible explicit waiver produces a degraded
receipt outside the complete grant-subset claim. Therefore a
verified enforced receipt cannot silently retain broader authority in an owned
domain.

\paragraph{Worker authority is bound before execution.}
The selected backend must complete descriptor cleanup and its confinement
setup before untrusted import. The Landlock and bubblewrap paths use different
activation implementations and require separate evidence. The enforced contract
binds the observed worker to the request and grant before the release barrier;
ordinary worker output cannot substitute for setup evidence.

\paragraph{Framework effects remain mediated.}
For a certified router path, dispatch consumes authorization for the same
principal and immutable request. State, model, and output effects require their
own operations; authorization for tool invocation does not authorize them.

Under these assumptions, exact and tightened enforcement support
Equation~\ref{eq:effect} for the covered routes and host authority domains.
The application canaries and native-chain checks test instances of effect
containment; the admission controls test changed bindings and missing manifest
permissions. The metadata census tests a host capability boundary. These
experiments do not discharge every inclusion for every resource mediator.
This subset relation does not guarantee useful execution or successful
completion. The current component evidence does not establish the assumptions
for every adapter or upstream path, and is not a whole-system theorem.

\section{Limitations}
\label{sec:limitations}

\paragraph{Coverage and trust.}
The complete-mediation obligation applies to admitted deployments, not arbitrary
LangGraph programs. General graph, backing-store, checkpoint-history, callback,
and publication paths still have placement or composition gaps. Source-body
admission covers its restricted function bodies and monitored terminals, not
imports or arbitrary Python. Runtime MAC refuses unsupported graph shapes and
requires trusted bootstrap in each interpreter; it is not machine-wide policy.
Coordinator code, privileged brokers, kernels, and launchers remain trusted.
Receipts are local software-rooted evidence, not remote hardware attestation.

\paragraph{Resource and flow semantics.}
SQLite supports a fixed record schema, not arbitrary queries; the pump is a
simulator with a trusted mediator. Other services need adapters at their resource
boundary. Provenance covers instrumented dependencies and conservative read
bounds, not unreported native effects. Classifier errors remain possible;
an analyzer timeout prevents late commits but cannot forcibly terminate a
Python thread. Landlock restricts live objects without providing snapshot
integrity or general metadata hiding.

\paragraph{Deployment and evaluation.}
Versioned bundles cover declared contents, not inferred dependency closure.
Store protection, static-specification retention, and pruning integration have
separate assumptions; deployment binding is specific to the bubblewrap path.
The evaluation has one protected application computation and narrow admitted-API
coverage. The native chain uses a distinct exec-enabled profile, without a
Landlock process-count ceiling. The execution-only replay omits authorization,
audit, and model calls, so it cannot replace complete-path costs.
One model-driven injection batch generates zero forbidden attempts and provides
no conditional enforcement-success estimate. Broader protected applications,
semantic-broker and sealed-MAC ablations, host changes, races, and persistent
container reuse remain unmeasured on a single frozen release. Raw archives and
that release remain necessary for a reproducible submission.

\section{Related Work}

\paragraph{Agent policies and information flow.}
Progent enforces tool-name/argument policies and checks whether generated
updates narrow privileges or require approval~\cite{progent}. Conseca explores
contextual, human-verifiable policy generation~\cite{conseca}; AgentSpec supplies
trigger/predicate rules and runtime interventions~\cite{agentspec}. These are
policy and enforcement contributions. \sys supplies a lower boundary for the
effects of the implementation that an allowed call enters.

CaMeL tracks dependencies in a restricted interpreter~\cite{camel}; FIDES
tracks confidentiality and integrity with selective exposure of planner
variables~\cite{fides}. Their flow precision exceeds \sys's conservative
treatment of opaque transformations. SEAgent and FORGE/SASY enforce policies
over agent interactions or event histories~\cite{seagent,forge}. \sys's
instrumented provenance can carry such evidence to fixed policy, but this
interface is not a reproduction of their analyses or guarantees.

\paragraph{Isolation and policy projection.}
IsolateGPT isolates hub and app processes, restricts syscalls and resources,
and mediates collaboration with user permissions~\cite{isolategpt}. Its
permission interface is complementary to our invocation-resource contract.
Nono and Sandlock confine native tools without requiring restricted source
admission~\cite{nono,sandlock}. APF supplies grants, mandatory forbids, and
extensible projection to runtime enforcement surfaces~\cite{apf,apfprojection}.
Its documented projection occurs when an authored bundle is loaded, rather
than at each tool invocation. \sys additionally derives a principal-specific
grant from requirements and binds its semantic and host obligations to execution.

\paragraph{Confinement mechanisms.}
Capsicum supplies capability-based confinement for UNIX~\cite{capsicum};
gVisor interposes an application kernel to reduce host-kernel exposure~\cite{gvisor};
Firecracker uses microVM isolation for serverless workloads~\cite{firecracker}.
Our Linux adapters fit existing process deployments using Landlock, seccomp,
and optionally bubblewrap. This choice does not establish superiority to VMs.
These confinement mechanisms still need semantic brokers and a contract linking
agent requirements to per-principal authority.

\paragraph{Agent-security evaluation.}
AgentDojo, InjecAgent, and ASB measure behavioral attack success and
utility~\cite{agentdojo,injecagent,asb}. Our deterministic canaries instead isolate
authority retained inside an approved implementation. An injection that produces
no forbidden attempt cannot measure this conditional enforcement boundary.

\paragraph{Reference monitors and hook placement.}
EC separates compartment identification from ECK's enforcement and protects
the monitor itself~\cite{khan2023ec}. Flask separates policy decisions from
object-manager enforcement~\cite{spencer1999flask}; LSM provides fixed hooks for
replaceable restrictive policies~\cite{wright2002lsm,linuxlsm}. User-space SELinux
object managers extend that separation beyond kernel
objects~\cite{selinuxnotebook,sepgsql}. \sys applies it to agent grants across
framework and resource boundaries. Authorization-hook placement still needs
independent analysis~\cite{zhang2002cqual}.

\paragraph{Deployments and authorization.}
Flatpak/OSTree separate applications from shared runtimes; portals mediate host
access~\cite{flatpak,ostree,portals}. \sys adds invocation identity and
authorization to selected deployments. Cedar supplies typed authorization with
forbid-overrides composition~\cite{cedar}; Linux mechanisms enforce the surviving
resource authority. A general desktop-portal integration is outside this work.

\section{Conclusion}

Agent policies must constrain effects after a request is approved. \sys turns
manifest proposals and principal/operator policy into invocation grants enforced
by runtime APIs, semantic brokers, and host adapters. Explicit lowering and
activation preserve authority across those boundaries; independent analyses
reuse the enforcement infrastructure.

\section{Ethical Considerations}

The bypass canaries target deliberately vulnerable tools in temporary
directories, synthetic databases, and loopback services. They do not probe or
modify third-party deployments. Canary values are fake and audit logs hash
arguments by default.

A security framework can create false confidence when its placement or host
support is incomplete. \sys mitigates that risk by denying unsupported grants,
stamping waivers as degraded, publishing the protected-operation inventory, and
separating component evidence from system claims. Operators remain responsible
for policy correctness, TCB maintenance, user notice, and recovery from
\code{INDETERMINATE} operations.
